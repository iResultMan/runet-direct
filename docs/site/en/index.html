runet-direct
VPN always on

Foreign sites go through the VPN, Russian sites go direct. Banks, Gosuslugi and mail open by themselves, no need to switch the VPN off.

Download the installer Source on GitHub Free, open source, 1.4 MB

No more switching the VPN

Normally you have to choose. With the VPN on, banks and Gosuslugi do not open or ask for extra verification. With the VPN off, foreign sites stop working. So you switch it back and forth and try to remember what is on right now.

With runet-direct the VPN is always on. The service splits the traffic by itself: Russian addresses go direct, everything else goes through the VPN.

Banks, Gosuslugi, mail
They open at once, as on a plain connection. No need to turn the VPN off.
Foreign sites
They use the VPN all the time, not only until you switch it off for a bank.
What you do
Nothing. No switching the VPN, no remembering whether it is on.

One command to check

Open a terminal and type runet-direct status. If the last line says Health: OK, Russian addresses go direct and everything else stays where you left it.

The service starts with your computer, downloads the list of Russian addresses (published by the European registry RIPE NCC) and refreshes it monthly. If something wipes the routes, such as tethering from a phone or a network change, it puts them back by itself.

It does not matter which VPN you use

The program does not try to find out which VPN you run and does not depend on its name. It checks the outcome: where a Russian address would really go.

If a VPN puts its own rule in front of ours and captures the traffic, the service moves its rule above it and logs that. If it cannot be fixed, the service says so instead of staying silent.

What the Linux tests cover

VPN as the default route
Russian addresses leave through the wire, the rest enter the tunnel.
VPN with 0/1 and 128/1 halves
The same result. Those routes are less specific than ours.
VPN placed its rule earlier
Our rule moves above it: from 2500 to 999, then to 499 when the VPN went lower.
Gateway change and a lost rule
Routes are repointed to the new gateway, and the rule comes back within two seconds.

macOS and Windows have no rule table: the most specific route wins. Installation and startup there are checked by automated builds on real systems.

Install

Windows 10 and 11

Download the file, run it and click Install. It asks for administrator rights.

Windows may say “Unknown publisher”: a free project has no paid signature. Click “More info”, then “Run anyway”.

runet-direct-setup.exe

macOS 11 and newer

One file for Intel and Apple Silicon. Open it, click Continue, then Install and enter your Mac password.

If macOS says it cannot verify the developer, right-click the file, choose Open and confirm.

runet-direct.pkg

Linux

Ubuntu, Debian, Mint: double-click the downloaded .deb. Fedora and others: .rpm. Needs systemd. ARM builds are on the releases page.

Or in one line, on any distribution:

curl -fsSL https://raw.githubusercontent.com/iResultMan/runet-direct/main/install.sh | sudo sh
runet-direct.deb

There is nothing to configure. A minute after installing, run runet-direct status. All files, with checksums, are on the releases page.

Control

Everything the service does is available as commands. They have --json output and stable exit codes, so other programs drive the service the same way you do.

runet-direct status
state of the service and the routes
runet-direct check bank.ru
where this address would go: direct or into the VPN
runet-direct pause --for 1h
everything through the VPN for an hour, for example to see a site as a foreigner would
runet-direct exclude example.com --for 30m
this site through the VPN, then it reverts by itself
runet-direct add 203.0.113.0/24
always direct for this network; a file with a list works too
runet-direct config set ipv6.enabled false
leave IPv6 alone, IPv4 keeps working

Questions

Do I have to switch anything on or off together with the VPN?

No. The service runs all the time and does not depend on whether the VPN is on at that moment. Turn the VPN on once and forget it: Russian sites go direct, the rest goes through it.

Is it safe?

The program does not read or intercept traffic. It only adds routes to the system table and removes them when you uninstall it. The code is open under the MIT license. Release files carry checksums and a build-provenance attestation.

Where does it connect?

Once a month it downloads the address list from RIPE NCC. Nowhere else. No telemetry, no account.

What if the VPN disconnects?

Russian addresses keep going direct; everything else behaves the way your system is set up. The service does not need the VPN.

How do I send one site through the VPN?

Paste the link straight from the browser: sudo runet-direct exclude https://site.ru/any-page. You do not need to know any address ranges: the program takes the addresses the site name points to right now and refreshes them every few hours. To undo: sudo runet-direct remove site.ru. For a limited time: add --for 1h.

A name with and without www behaves the same. For a site with its subdomains: sudo runet-direct exclude '*.site.ru' (quoted; without quotes you can write .site.ru). The mask checks the site itself and the most common subdomains (api, m, static, cdn, lk, login and more); add any other subdomain by its own name.

If a site has very many addresses (it sits behind a delivery network), it may not work for all of them at once: check with runet-direct check site.ru.

One site still opens through the VPN. Why?

The list is built from Russian address blocks. A site behind a foreign delivery network is not in it. Add it by hand; pasting a link works: sudo runet-direct add https://site-name.ru. Verify with runet-direct check site-name.ru.

Does it work with IPv6?

Yes. IPv4 and IPv6 are switched separately. If you have no IPv6, the service simply skips it.

How do I uninstall it?

Windows: Settings, Apps, runet-direct. macOS: sudo runet-direct uninstall. Linux: sudo apt remove runet-direct or sudo dnf remove runet-direct. The routes are removed on uninstall.

What about my VPN’s kill switch?

If the kill switch is a firewall rule, it blocks direct traffic too and the program cannot change that. Turn the switch off or add an exception for your connection.
