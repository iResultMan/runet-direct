## В чём проблема

Когда VPN включён, через него идёт *всё*, в том числе российские банки, Госуслуги, маркетплейсы и почта. Многие из них
не пускают иностранные адреса, просят дополнительное подтверждение или просто грузятся медленнее. Приходится выключать
VPN ради них, затем снова включать ради всего остального и помнить, в каком состоянии он сейчас. Раздельное
туннелирование по приложениям не помогает, когда один браузер открывает оба мира.

**С runet-direct ничего переключать не нужно.** VPN включён всегда: зарубежные сайты идут через него, российские
открываются напрямую, сами.

## Что делает runet-direct

```
                       ┌── российский адрес ───────────────────────► банки, Госуслуги, почта   (напрямую)
 ваш компьютер ────────┤
                       └── всё остальное ───► [ туннель VPN ] ─────► остальной мир
```

Это небольшая фоновая служба. Она знает, какие адресные блоки принадлежат России (из открытого реестра RIPE NCC),
отправляет именно их через обычное подключение, а всё остальное оставляет вашему VPN. Какой у вас VPN, ей неважно: она
на него не смотрит. Она проверяет *результат*: куда на самом деле уйдёт российский адрес.

- **Работает с любым VPN.** Linux, macOS и Windows. IPv4 и IPv6, каждый включается отдельно.
- **Сама себя чинит.** Раздача интернета с телефона, новая сеть, VPN, который перекраивает правила: маршруты
  возвращаются за секунды. Если VPN встал со своим правилом *раньше* нашего, служба это замечает и поднимает своё выше.
- **Один маленький файл.** 1,4 МБ, без среды выполнения, ничего дополнительно ставить не нужно. Без телеметрии и
  учётной записи.
- **Управляется скриптами.** У каждой команды есть `--json` и постоянные коды выхода, поэтому другие программы могут её
  вызывать.

## Установка

| Система | Что сделать |
| --- | --- |
| **Windows 10/11** | Скачайте [`runet-direct-setup-x86_64.exe`](https://github.com/iResultMan/runet-direct/releases/latest/download/runet-direct-setup-x86_64.exe), запустите и нажмите «Установить». |
| **macOS 11+** | Скачайте [`runet-direct-macos.pkg`](https://github.com/iResultMan/runet-direct/releases/latest/download/runet-direct-macos.pkg) (Intel и Apple Silicon), откройте, нажмите «Продолжить» и «Установить». |
| **Ubuntu / Debian / Mint** | Скачайте [`runet-direct-linux-amd64.deb`](https://github.com/iResultMan/runet-direct/releases/latest/download/runet-direct-linux-amd64.deb) и дважды щёлкните по нему (или `sudo apt install ./файл.deb`). |
| **Fedora и другие системы с RPM** | [`runet-direct-linux-x86_64.rpm`](https://github.com/iResultMan/runet-direct/releases/latest/download/runet-direct-linux-x86_64.rpm): `sudo dnf install ./файл.rpm`. |
| **Любой Linux или macOS, одной строкой** | `curl -fsSL https://raw.githubusercontent.com/iResultMan/runet-direct/main/install.sh \| sudo sh` |
| **Windows, одной строкой** (PowerShell от администратора) | `irm https://raw.githubusercontent.com/iResultMan/runet-direct/main/install.ps1 \| iex` |

Версии для ARM (`arm64`, `aarch64`) лежат на [странице релизов](https://github.com/iResultMan/runet-direct/releases/latest).
Настраивать ничего не нужно. При первом запуске один раз скачивается список адресов (около 18 МБ).

> **О предупреждениях.** Установщики не подписаны платным сертификатом (проект бесплатный). Windows может написать
> «Неизвестный издатель»: нажмите «Подробнее», затем «Выполнить в любом случае». macOS может сообщить, что не может
> проверить разработчика: откройте файл правой кнопкой мыши и выберите «Открыть». У каждого файла релиза есть
> контрольная сумма SHA-256 и подтверждение происхождения сборки
> (`gh attestation verify <файл> --repo iResultMan/runet-direct`), так что скачанное можно проверить.

## Чем отличается

| | Раздельное туннелирование в приложении VPN | Самодельные скрипты маршрутов | **runet-direct** |
| --- | --- | --- | --- |
| Работает с любым вашим VPN | только если приложение это умеет | привязано к одной настройке | **да** |
| Знает российские адресные блоки | список ведёте вы | ведёте вы | **да, обновляется раз в месяц** |
| Переживает смену сети | не относится | только если вы это написали | **да, за секунды** |
| Замечает, что VPN перехватил трафик | не относится | нет | **да** |
| Windows, macOS и Linux | не относится | одна система | **все три** |
| Пауза с таймером | нет | нет | **`pause --for 1h`** |

## Повседневные команды

Всё, кроме `status`, `check`, `list` и `config`, требует прав root / администратора.

| Команда | Что делает |
| --- | --- |
| `status [--json]` | Состояние службы и маршрутов. Код выхода: `0` всё хорошо, `1` работает, но найдена проблема, `3` установлена, но не запущена, `4` не установлена. |
| `check [--json]` | Проверить *реальное* состояние: спрашивает у системы, куда пойдут контрольные адреса. Код `0` норма, `1` проблема. |
| `check ЦЕЛЬ` | Куда пойдёт этот IP, сеть или домен? Печатает `direct via <интерфейс>` или `TUNNEL`. Код `0` напрямую, `1` через туннель. |
| `pause [--for 1h]` / `resume` | Пустить **всё** через VPN на время, например посмотреть сайт так, как его видит иностранец. |
| `add ЦЕЛЬ...` | Всегда напрямую: ссылка из браузера (`https://сайт.ru/страница`), домен, IP, `a.b.c.d/n` или IPv6-префикс. `--file ФАЙЛ` (или `-` для стандартного ввода) принимает целый список. |
| `exclude ЦЕЛЬ...` | Никогда напрямую, даже если адрес входит в российский список. Принимает те же цели, включая ссылки, и маски: `exclude '*.сайт.ru'` (в кавычках; `.сайт.ru` кавычек не требует). `--for 30m` / `--until <время>` делает исключение временным: оно снимется само. |
| `remove ЦЕЛЬ...` / `list [--json]` | Править / показать ручной список. |
| `export [--format cidr\|wireguard\|openvpn\|amnezia]` | Выдать российский список адресов (вместе с вашим ручным) для другого VPN-ПО, см. ниже. Права администратора не нужны. |
| `config get КЛЮЧ` / `config set КЛЮЧ ЗНАЧЕНИЕ` | Прочитать или изменить одну настройку, например `config set ipv6.enabled false`. Комментарии в файле сохраняются. |
| `install` / `uninstall [--purge]` | Установить службу и включить автозапуск / удалить её **и все добавленные ею маршруты**. |
| `start` / `stop` / `restart` / `enable` / `disable` | Управление службой. **`stop` оставляет маршруты на месте**, чтобы рунет не вернулся в VPN молча. |
| `apply` / `refresh` / `clear` | Разовая синхронизация / скачать список сейчас / снять все маршруты. |

`runet-direct --help` показывает всё. Другим программам стоит опираться на `--json` и коды выхода, а не на текст.

## Список для другого VPN-приложения

Если разделение делает сам VPN-клиент (или вы настраиваете роутер), `runet-direct export` выдаёт тот же список в виде,
который понимает это ПО. В него входит ваш `manual.list`, а ваши исключения вычтены.

| Команда | Результат |
| --- | --- |
| `runet-direct export --format cidr` | Российские блоки, одна сеть в строке. |
| `runet-direct export --format wireguard` | Одна строка `AllowedIPs = ...`, покрывающая всё, **кроме** российских блоков, для раздела `[Peer]`. Список большой (около 22 000 сетей), на телефоне импорт будет медленным. |
| `runet-direct export --format openvpn` | Строки `route ... net_gateway`, которые держат российские блоки вне туннеля (IPv4). |
| `runet-direct export --format amnezia` | JSON-список сайтов для AmneziaVPN: «адреса из списка не открывать через VPN» (IPv4). |

`--output ФАЙЛ` записывает файл, `--ipv4-only` убирает IPv6. Служба должна один раз скачать список (это делает `install`).

## Настройки

Создаются при установке, все параметры описаны комментариями. Поправили: `runet-direct restart` (или `config set`).

| | Linux | macOS | Windows |
| --- | --- | --- | --- |
| Настройки, `manual.list` | `/etc/runet-direct/` | `/Library/Application Support/runet-direct/` | `%ProgramData%\runet-direct\` |
| Данные, состояние | `/var/lib/runet-direct/` | (там же) | (там же) |
| Журнал | `journalctl -u runet-direct` | `/var/log/runet-direct.log` | `%ProgramData%\runet-direct\runet-direct.log` |

В `manual.list` ваши записи, по одной в строке (слово `direct` по умолчанию можно опустить):

```
direct 203.0.113.0/24     # всегда напрямую
direct bank.example.com   # домены переразрешаются каждые несколько часов
vpn    198.51.100.7       # никогда напрямую, даже если адрес входит в российский блок
```

`config.toml`: `[ipv4]` / `[ipv6]` `enabled`; `[routing]` `table`, `priority`, `interface`, `ignore_interfaces`; `[ru]`
`enabled`, `country`, `source_url`, `refresh_days`, `min_prefixes`; `[daemon]` `interval_seconds`. Выключенное семейство
адресов остаётся в полном покое (маршруты, добавленные для него раньше, один раз снимаются).

## Честные ограничения

- «Аварийный выключатель» VPN, сделанный правилом файрвола, по замыслу блокирует и прямой трафик, поэтому сводит работу
  этой программы на нет.
- Для самой первой загрузки нужен рабочий интернет. Дальше служба живёт на сохранённой копии списка и обновляет её раз
  в месяц; неудачная или обрезанная загрузка уже стоящие маршруты не трогает.
- Список строится по российским адресным блокам. Сайт за зарубежной сетью доставки в него не попадёт; добавьте его
  командой `runet-direct add сайт.ru`.
- Linux покрыт сквозными тестами (сетевое пространство имён, настоящая служба systemd, `.deb` в контейнере). macOS и
  Windows используют тот же движок, и CI устанавливает и проверяет их на настоящих машинах, но в реальной жизни они
  проверены меньше. Отчёты приветствуются.
- В пути должен быть `curl` (он есть в Windows 10+, macOS и почти любом Linux).

## Как это устроено, коротко

- **Linux:** отдельная таблица маршрутов и одно правило «сначала загляни в мою таблицу» с меньшим номером приоритета,
  чем у любого правила VPN. Когда маршруты на месте, служба спрашивает у ядра, куда реально пойдёт российский адрес;
  если его перехватывает правило VPN, наше встаёт сразу над ним.
- **macOS и Windows:** обычные маршруты к физическому шлюзу; побеждает самый точный маршрут, а российские блоки
  намного точнее «ловящих всё» маршрутов VPN.
- Физическое подключение определяется по тому, чем является интерфейс (железо или виртуальный), а не по названию VPN.

Причины всех неочевидных решений описаны в [docs/design.md](docs/design.md).
