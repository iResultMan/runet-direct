# runet-direct

**Рунет — мимо VPN. Поставил и забыл.**

[English version](README.md)

Когда VPN включён, через него идёт *всё*, в том числе российские банки, госпорталы, площадки и почта. Многие из
них не пускают иностранные адреса или просто работают медленнее. `runet-direct` — небольшая фоновая служба: трафик
к российским адресным блокам она отправляет напрямую, через обычное подключение, а остальное продолжает идти через
VPN. Работает с любым VPN: какой именно у вас стоит, ей знать не нужно.

- Один статический файл, ничего больше ставить не надо. Linux, macOS и Windows. IPv4 и IPv6, каждый включается отдельно.
- Сама регистрируется как системная фоновая служба и сама чинит свои маршруты при любых изменениях сети.
- Управляется из командной строки, умеет выдавать JSON и имеет стабильные коды выхода — её могут вызывать другие программы.

## Установка

**Linux / macOS** (нужен `curl`; на Linux ещё `ip` из iproute2 и systemd для службы):

```bash
curl -fsSL https://raw.githubusercontent.com/iResultMan/runet-direct/main/install.sh | sudo sh
```

**Windows** (PowerShell, запущенный *от администратора*):

```powershell
irm https://raw.githubusercontent.com/iResultMan/runet-direct/main/install.ps1 | iex
```

**Из исходников** (Rust 1.89+): `cargo build --release`, затем `sudo ./target/release/runet-direct install`
(в Windows — `runet-direct.exe install` из консоли администратора).

Установщик скачивает один файл, проверяет контрольную сумму SHA-256, регистрирует и запускает службу и ждёт первой
синхронизации (один раз скачивается около 18 МБ открытых данных RIPE). Дальше проверка одной командой:

```bash
runet-direct status
```

Повторный `install` обновляет программу на месте и сохраняет ваши настройки.

К файлам релиза приложены подтверждение происхождения сборки (attestation) и файл SHA-256. Проверить скачанное
независимо от установщика: `gh attestation verify <файл> --repo iResultMan/runet-direct`.

## Команды

Всё, кроме `status`, `check`, `list` и `config`, требует прав root / администратора.

| Команда | Что делает |
| --- | --- |
| `install [--no-start]` | Установить службу, включить автозапуск, запустить. Можно повторять (обновление). |
| `uninstall [--purge]` | Остановить и удалить службу **и все добавленные ею маршруты**. `--purge` ещё удаляет настройки и данные. |
| `start` / `stop` / `restart` | Управление службой. **`stop` оставляет маршруты на месте**, чтобы рунет не вернулся в VPN молча. |
| `enable` / `disable` | Запускать / не запускать при загрузке системы. |
| `status [--json]` | Состояние службы и маршрутов. Код выхода: `0` всё хорошо, `1` работает, но найдена проблема, `3` установлена, но не запущена, `4` не установлена. |
| `check [--json]` | Проверить *реальное* состояние: спрашивает у системы, куда пойдут контрольные адреса. Код `0` — норма, `1` — проблема. |
| `check ЦЕЛЬ` | Куда пойдёт этот IP, сеть или домен? Печатает `direct via <интерфейс>` или `TUNNEL`. Код `0` — напрямую, `1` — через туннель. |
| `apply` | Один раз привести маршруты в нужное состояние, без демона. |
| `refresh` | Скачать список адресов сейчас и применить. |
| `clear` | Снять все маршруты и правило, которые поставила программа. |
| `add ЦЕЛЬ...` | Всегда напрямую: IP, `a.b.c.d/n` или имя домена. |
| `exclude ЦЕЛЬ...` | Никогда напрямую, даже если адрес входит в российский список. Главнее всего остального. |
| `remove ЦЕЛЬ...` / `list [--json]` | Править / показать ручной список. |
| `pause [--for 1h]` / `resume` | Пустить **всё** через VPN на время (или до `resume`) — например, проверить, как сервис ведёт себя с иностранного адреса. |

`add`, `exclude` и `remove` принимают `--file ФАЙЛ` (одна цель в строке, `-` — стандартный ввод), так что другая
программа может передать целую таблицу. `add` и `exclude` принимают `--for 30m` / `--until 2026-10-14T18:00:00Z`:
запись сама перестаёт действовать, даже если создавшая её программа упала, а служба просыпается ровно в этот
момент. `status` показывает действующую паузу.
| `config` / `config path` | Показать действующие настройки / расположение файлов. |
| `config get КЛЮЧ` / `config set КЛЮЧ ЗНАЧЕНИЕ` | Прочитать или изменить одну настройку, например `ipv6.enabled`; комментарии в файле сохраняются, изменение проверяется и применяется сразу. |
| `run [--log-file F]` | Запустить демон на переднем плане (именно это выполняет служба). |

Другим программам стоит опираться на `--json` и коды выхода, а не на человекочитаемый текст.

## Настройки

Файлы создаются при установке, все параметры в них описаны комментариями. Поправили — `runet-direct restart`.

| | Linux | macOS | Windows |
| --- | --- | --- | --- |
| Настройки, `manual.list` | `/etc/runet-direct/` | `/Library/Application Support/runet-direct/` | `%ProgramData%\runet-direct\` |
| Данные, состояние | `/var/lib/runet-direct/` | (там же) | (там же) |
| Журнал | `journalctl -u runet-direct` | `/var/log/runet-direct.log` | `%ProgramData%\runet-direct\runet-direct.log` |

В `manual.list` — ваши записи, по одной в строке (слово `direct` по умолчанию можно опустить):

```
direct 203.0.113.0/24     # всегда напрямую
direct bank.example.com   # домены переразрешаются каждые несколько часов
vpn    198.51.100.7       # никогда напрямую, даже если адрес входит в российский блок
```

Параметры `config.toml`: `[ipv4]` / `[ipv6]` `enabled`; `[routing]` `table`, `priority`, `interface`,
`ignore_interfaces`; `[ru]` `enabled`, `country`, `source_url`, `refresh_days`, `min_prefixes`; `[daemon]`
`interval_seconds`.

**IPv4 и IPv6 независимы.** `runet-direct config set ipv6.enabled false` оставляет IPv6 в покое (и убирает
IPv6-маршруты, добавленные этой программой раньше); такой же переключатель есть для `ipv4`. Если у машины вообще нет
IPv6, делать для него нечего, и состояние остаётся здоровым.

## Правда ли работает с моим VPN?

Знать ваш VPN службе не нужно. Простыми словами:

- **Linux.** Маршруты лежат в отдельной таблице, и добавлено одно правило «сначала загляни в мою таблицу». VPN может
  поставить своё правило *впереди* нашего. Поэтому служба не верит наличию правила: она спрашивает у системы, куда
  реально пойдёт российский адрес. Если ответ «в VPN» — она поднимает своё правило над тем, что перехватывает, и
  пишет об этом в журнал. Проверка идёт при каждом событии сети.
- **macOS и Windows.** Правил там нет: побеждает самый точный маршрут, а российские блоки гораздо точнее, чем
  «ловящие всё» маршруты VPN, так что выигрывают сами.
- Физическое подключение определяется по тому, чем является интерфейс (настоящее железо или виртуальный), а не по
  названию VPN.

Ограничение: «аварийный выключатель» VPN, реализованный через файрвол, по замыслу блокирует прямой трафик и
сводит работу этой программы на нет.

## Требования и ограничения

- В пути должен быть `curl` (есть в современных Windows 10+, macOS и почти любом Linux).
- Для первой загрузки нужен рабочий интернет. Потом служба живёт на сохранённой копии списка и раз в месяц её
  обновляет; неудачная или обрезанная загрузка уже установленные маршруты не трогает.
- В Windows служба — это задача Планировщика, запускаемая при загрузке от имени SYSTEM (перезапускается, если
  завершилась с ошибкой); в macOS — launchd; в Linux — systemd. С другой системой инициализации запускайте
  `runet-direct run` сами.
- Linux покрыт сквозными тестами (сетевое пространство имён, настоящая служба systemd). macOS и Windows используют
  тот же движок и проверяются дымовыми тестами в CI на настоящих машинах, но в реальной жизни проверены меньше.

## Разработка

```bash
cargo test                                          # юнит-тесты, любая ОС
cargo build && sudo tests/linux-netns.sh target/debug/runet-direct   # сквозной тест маршрутизации в одноразовом пространстве имён
```

`tests/linux-service.sh` устанавливает настоящую службу и предназначен только для одноразовых машин
(`RUNET_TEST_DISPOSABLE=1`). Устройство и причины неочевидных решений — в [docs/design.md](docs/design.md).
